# Контракт API модерации (нужно реализовать на бэкенде)

Клиент готов и уже вызывает эти эндпоинты (`lib/services/api_service.dart`,
раздел «Модерация UGC»). Пока их нет, кнопки жалобы/блокировки будут
показывать ошибку — **до подачи в сторы бэкенд обязателен**.

Основание: App Store Review Guideline 1.2 (User-Generated Content) и политика
Google Play «User Generated Content». Требуются одновременно: подача жалобы,
блокировка пользователя, реакция модератора в течение 24 часов.

---

## 1. `POST /api/reports`

Подать жалобу. Авторизация обязательна.

```jsonc
// запрос
{
  "target_type": "post",        // post | assignment | submission | ai_message | user
  "target_id": 123,
  "reason": "abuse",            // spam | abuse | inappropriate | academic | other
  "comment": "необязательный текст, до 500 символов"
}
```

**Ответы**

| Код | Смысл |
|-----|-------|
| 201 | жалоба создана |
| 409 | этот пользователь уже жаловался на этот объект — клиент показывает `report_already`, а не ошибку |
| 404 | объект не найден |
| 429 | слишком много жалоб (защита от спама) |

Рекомендуется: rate limit ~10 жалоб в час на пользователя; при создании —
push админам с `data.type = "admin_report"` (`PushService._routeByType` его
уже обрабатывает и переключает на вкладку админки).

---

## 2. `POST /api/users/{id}/block` · `DELETE /api/users/{id}/block`

Заблокировать/разблокировать пользователя от имени текущего.

Блокировка **взаимная по видимости**: заблокированный не должен видеть
контент заблокировавшего и наоборот — иначе блокировка не защищает от
преследования.

| Код | Смысл |
|-----|-------|
| 204 | выполнено (идемпотентно: повторный вызов — тоже 204) |
| 400 | попытка заблокировать самого себя |
| 404 | пользователь не найден |

---

## 3. `GET /api/users/blocked`

Список заблокированных текущим пользователем.

```jsonc
[
  { "id": 42, "full_name": "Иван Петров", "email": "ivan@example.com" }
]
```

Клиент терпим к формату: принимает и голый список, и `{"items": [...]}`.

---

## 4. `GET /api/admin/reports?open=true`

Очередь модерации. **Только роль admin** (иначе 403).

```jsonc
[
  {
    "id": 7,
    "target_type": "post",
    "target_id": 123,
    "reason": "abuse",
    "comment": "текст жалобы",
    "reporter_name": "Иван Петров",
    "reporter_email": "ivan@example.com",
    "created_at": "2026-07-30T12:00:00",   // naive UTC, как остальные даты
    "resolved": false
  }
]
```

---

## 5. `POST /api/admin/reports/{id}/resolve`

Закрыть жалобу. Только admin.

```jsonc
{ "action": "dismissed" }   // необязательно: dismissed | content_removed | user_blocked
```

Ответ 200/204.

---

## Серверная фильтрация

Помимо клиентского скрытия (`ModerationProvider`), выдача должна фильтроваться
на сервере — иначе контент заблокированного вернётся после переустановки
приложения и будет виден в push-уведомлениях:

- `GET /posts/` — исключить авторов из блок-листа запрашивающего;
- `GET /assignments/`, `GET /submissions/` — то же;
- push-уведомления — не отправлять о событиях от заблокированных.

## Формат дат

`created_at` — naive ISO без таймзоны, трактуется как UTC (как и везде в API,
см. `lib/utils/dates.dart::parseServerDate`).
